Campagnes › partie 12b, emails et SMS — proposition. Chaque campagne a ses messages (un email ou un SMS écrit pour les professionnels de santé), écrits dans un éditeur visuel, souvent à partir d'un modèle de la bibliothèque du laboratoire (Engager › Modèles). Un message est approuvé par une autre personne avant de pouvoir partir. L'envoi lui-même (à qui, quand, le suivi) arrive en 12c. Les points à approuver sont en bas.

  1. Un éditeur visuel (décidé le 14 nov. ; nouveau paquet Tiptap) : gras, italique, titres, listes, liens, images, bouton. Proposé : les images sont envoyées dans le stockage du laboratoire (MinIO) et l'email les montre par un lien ; elles comptent dans l'espace du laboratoire, comme les aides de visite.
  2. Proposé : un seul habillage pour tous les emails du laboratoire (logo, couleur du bandeau, texte du pied de page), dans ⚙ Réglages des campagnes. Un modèle ne contient alors que le contenu (objet, texte, pièces jointes) : chaque email du laboratoire garde la même allure, et changer le logo ne demande pas de reprendre tous les modèles. Les anciens modèles avaient chacun leur propre HTML complet.
  3. Champs à insérer (décidé) : nom de la campagne, code de la campagne, année, nom du professionnel : « Dr » + son nom pour un médecin ou un dentiste (« Dr Yacine Cherif »), le nom seul pour les autres (décidé le 14 nov. : la fiche n'a qu'un nom, pas de titre ni de prénom à part). Choisis dans « Insérer un champ », affichés comme une pastille, jamais tapés à la main ; l'aperçu remplit les champs avec un exemple.
  4. Email et SMS (décidé) : les deux s'écrivent dès maintenant. Un SMS est du texte simple avec un compteur (160 caractères par SMS, 70 avec des lettres arabes) ; il n'apparaît que si le laboratoire a channel.sms. En 12c seuls les emails partent, jusqu'au choix d'un fournisseur SMS. Proposé : un SMS n'a ni pièce jointe ni image.
  5. Une bibliothèque de modèles (décidé) : Engager › Modèles, partagée par toutes les campagnes ; une marque facultative ; un canal (email ou SMS). Un message créé à partir d'un modèle en copie l'objet, le texte et les pièces jointes ; changer le modèle ensuite ne touche jamais le message. Le message garde « Modèle : Newsletter » pour information.
  6. Pièces jointes (décidé) : sur les modèles et sur les messages, 10 Mo chacune, comme l'API précédente. Proposé : elles comptent dans l'espace du laboratoire (refus quand il est plein), PDF, images, Word, Excel et PowerPoint seulement.
  7. Un nouveau laboratoire commence avec 3 modèles (décidé) : « Newsletter / annonce produit », « Invitation événement / webinaire », « Relance / rappel court », ceux de l'API précédente refaits pour l'éditeur. Le laboratoire peut les changer ou les supprimer.
  8. Approuvé par une deuxième personne (décidé) : l'auteur « Marque prête » ; une personne qui a le droit campaign-messages.approve approuve ou renvoie avec une raison ; seul un message approuvé peut partir (12c). Jamais l'auteur : refusé pour qui l'a écrit ou modifié en dernier, même s'il a le droit. Modifier un message approuvé le remet en brouillon (une confirmation le dit). Proposé : quatre états, Brouillon, Prête, Renvoyée, Approuvée (les états « archivé » et « annulé » de l'API précédente sont abandonnés) ; l'historique (qui a marqué prête, approuvé, renvoyé, pourquoi) est montré sur la page du message, lu du journal.
  9. « M'envoyer un test » (décidé) : à l'adresse de la personne connectée, avec les champs remplis par un exemple, par le canal email du laboratoire ; il compte dans le quota du mois. Proposé : possible à tout état, même brouillon ; l'objet commence par « [TEST] ».
  10. Droits (décidé) : les messages suivent campaigns.update (marketing) ; les modèles, un nouveau droit mail-templates (marketing) ; campaign-messages.approve aux admins, que le laboratoire peut donner à un autre rôle (Studio › Rôles). Proposé : les managers et délégués, qui voient la campagne, ne voient pas cet onglet.
  11. Proposé : supprimer. Un message se supprime tant qu'aucun envoi ne l'utilise (12c) ; un modèle se supprime toujours (les messages gardent leur copie, le lien « Modèle » disparaît) ou se désactive pour ne plus être proposé.
  12. Proposé : l'onglet s'appelle « Emails & SMS » et non « Messages », parce qu'une coche de la grille promo a déjà son « message » (l'argument du délégué). Dans le code, la table reste campaign_messages.
  13. Abandonné des anciennes applications : la boîte de code HTML et la note libre « Conditions d'envoi » (à qui et quand envoyer se choisit en 12c).
