Notifications (module 20a), proposition. Une ligne dans la cloche quand quelqu'un agit sur le travail d'une autre personne : frais approuvés ou refusés, plan envoyé, approuvé ou refusé, visite rejetée, visite planifiée par un responsable. Dans l'application seulement, pas d'e-mail. Exemple : Nadia (superviseure) refuse le plan de novembre de Karim (délégué) ; la cloche de Karim affiche 1 et la ligne ouvre son calendrier. Aujourd'hui : 24 nov. 2026. Les cadres pointillés orange sont à confirmer.

  1. Dans l'application seulement (décidé le 24 nov.) : pas d'e-mail, pas de SMS, pas de notification sur le téléphone. Un e-mail ne viendra que pour un événement qui en a vraiment besoin, fixé dans le code ; aucun en 20a.
  2. Les 7 événements de 20a (décidés un par un) : ① frais approuvés → la personne, une seule ligne par approbation (le mois entier = 1 ligne) ; ② jour de frais refusé → la personne, avec le motif ; ③ plan envoyé → tous les responsables actuels de la personne (sa liste « Dépend de »), personne au-dessus ; ④ plan approuvé → la personne ; ⑤ plan refusé → la personne, avec le motif ; ⑥ visite rejetée → la personne, une ligne par visite, avec la note ; ⑦ visite planifiée par un responsable → la personne, une ligne par visite.
  3. Personne n'est prévenu de sa propre action (choix pris, à corriger si besoin) : un responsable qui planifie une visite pour lui-même ne reçoit rien.
  4. Deux groupes (décidé) : Frais (①②) et Visites (③ à ⑦). Une icône par groupe sur chaque ligne, et un filtre sur la page.
  5. La cloche (décidé) : un nombre rouge des non lues (« 9+ » au-delà de 9), mis à jour chaque minute et au retour sur l'onglet. Le panneau montre les 10 dernières ; « Tout voir » ouvre la page Notifications.
  6. Lu / non lu (décidé) : une ligne devient lue quand on clique dessus (elle ouvre le jour de frais, le plan ou la visite) ; « Tout marquer comme lu » ; « Marquer comme non lu » sur une ligne lue. Ouvrir le panneau ne change rien. On ne supprime pas une ligne à la main.
  7. Gardées 90 jours (décidé) : chaque nuit, les lignes de plus de 90 jours partent, lues ou non. 90 est la valeur par défaut d'un réglage central (le même pour tous les labos). Le jour de frais, le plan ou la visite ne sont jamais touchés.
  8. Les textes (décidé) : la ligne garde l'événement et ses valeurs (Nadia, novembre, le motif) ; la phrase est écrite à l'affichage avec les textes du labo, dans la langue de la personne. Changer de langue change aussi les anciennes lignes.
  9. Interrupteurs (décidé) : pas d'interrupteur côté central. L'admin du labo allume ou éteint chaque événement dans Studio › Notifications (tous allumés au départ). Éteint : plus aucune nouvelle ligne de ce type ; les lignes déjà reçues restent. Les utilisateurs ne peuvent pas couper un événement pour eux-mêmes (plus tard si on le demande).
  10. 20b-1 (décidé le 24 nov., cadres 6 à 8) : Commandes : transmise → tous les responsables actuels de la personne ; validée, annulée (avec le motif), rouverte → la personne ; facturée → personne. Coaching : planifiée, déplacée (seulement si le jour change), annulée (avec le motif), validée (« à accepter ou refuser ») → la personne coachée ; acceptée, refusée (avec le motif) → le coach seulement. Professionnels : nouvelle proposition → tous les responsables actuels de la personne ; acceptée (ouvre le professionnel), refusée (avec le motif, ouvre « Mes propositions ») → la personne. Activités (l'ancienne « Visite Duo ») : une activité ajoutée par quelqu'un d'autre → la personne « Pour » et chaque personne liée. Commandes n'existe que si le labo a le module Commandes.
  11. Pas repris des anciennes applications : la demande de « cible temporaire » et la modification de contact (n'existent pas dans Delorc), l'export prêt, le message manuel à l'équipe (5 lignes), les alertes de fin de cycle et de synchronisation (jamais lancées).
  12. Plus tard (20b-2) : événements, veille concurrentielle, réclamations, validation des messages de campagne, enquêtes.
